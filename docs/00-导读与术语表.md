# 00 · 导读与术语表

> 这套文档讲的是一个叫「场记 SceneNote」的 App：**一个纯客户端（没有自己的服务器）的 AI 语音转文字 + 实时翻译 App**，用 Kotlin Multiplatform 同时做 Android 和 iOS。
> 这一篇告诉你：产品一句话是什么、文档怎么分、每篇给谁看、以及文档里那些"黑话"是什么意思。

---

## 一句话说清这个产品

**按一下，就进对的场景；旗舰功能是实时翻译。**

- **屏外（面对面）**：说话的人只管说，听的人戴上耳机就能实时听到译文。手机可以留在胸前口袋，不用举起来、不用看屏幕、不会外放，对方也不用碰你的手机。
- **屏内（看视频）**：手机里正在播的外语视频、网课、直播，译文字幕浮在画面上，或者译文配音进耳机（Android 能直接抓系统声音；iOS 主要支持相册 / 文件 / 直链视频）。
- **录音场景**：会议、口述成稿、方言家庭三张卡，一按就录，录完自动整理成能直接发出去的稿子。
- **一切都在你手机里**：识别可以完全离线，中 ↔ 英翻译也可以完全离线（端侧 NMT 模型）；想用云端（更准、更多语言）就填自己的 API Key，App 不内置任何 Key，也没有账号、没有服务器。系统自带的识别 / 翻译只作为 v1.1 的可选插件，两端能力不依赖系统 API。

- **要拍板的人**：01 → 10 → 12 → 附录 B 的"待决策"。

## 三条不能碰的红线

1. **没有后端**：不建服务器、不做账号、不做社区、不做自建云同步；多设备只靠系统能力（分享面板、AirDrop / Quick Share、局域网、蓝牙、平台云盘）。
2. **不内置任何 Key**：云端识别 / 翻译 / 润色只能用用户自己填的 Key 直连第三方；App 里不藏 Key（无后端下必被提取）。
3. **不谈商业模式**：文档里没有定价、付费、会员、增长章节。

## 术语表（黑话翻译）

### 产品词

| 词 | 意思 |
|---|---|
| 场记 / SceneNote | 产品名。"场"既是录音场景，也是面对面的现场、屏幕里的现场 |
| 场景卡 | 首页上的一张卡，把"什么语言、要不要翻译、翻成什么、什么口气、输出什么"打包好；按一下就开始 |
| 入口 | 不打开 App 也能触发场景的地方：控制中心按钮、Action Button、Android 磁贴、桌面小组件、快捷指令、耳机按键 |
| 零点击路径 | 从"想用"到"出结果"，用户被迫点几下。我们对每张 MVP 卡都数出来 |
| 五张 MVP 场景卡 | 面对面对话（置顶）、屏内字幕、会议、口述成稿（三张子卡）、方言家庭 |
| 屏外 / 屏内 | 屏外 = 用麦克风听真实世界；屏内 = 翻译手机自己正在播放或保存的视频 |
| M0–M12 | 屏外的 12 个模式编号（M2 空缺）。常用：M0 仅听、M1 耳听·面屏、M3 双屏对话、M4 速译卡片、M5 分耳、M8 双机私聊、M10 多人同传 |
| S1–S8 | 屏内的 8 个模式编号。常用：S1 系统字幕（Android）、S4 文件字幕（两端）、S8 外放旁听 |
| 单工 / 对话 | 单工 = 只往一个方向翻（我说→译出，或对方说→我听）；对话 = 双向轮流，自动判断谁在说 |
| 判向 | 对话模式里自动判断"这句是我说的还是对方说的"，从而决定往哪个方向翻 |
| 零社交摩擦 | 不掏手机、不外放、对方不膈应、公共场合不社死 |
| 黄标 | 外放（用手机喇叭播译文）的功能都标黄，只当降级选项，不放在主入口 |
| 升级阶梯 | M0 → M1 → M3 每一级只多一个动作，随时能退回 |
| 礼貌卡 | 把手机转向对方时，对方半屏先显示一句他的语言："我在用翻译听你说话，请正常说" |
| 留言卡 | 方言家庭场景的产物：一张图（方言原文 + 普通话）+ 一段音频，发到家庭群，长辈不用装 App |
| 对话卡片 / .voxnote / .scene / .srt | 产物文件：对话双语卡片图；带音频和文字的笔记包；场景配置包；字幕文件 |
| 知识库 / Vault | 你说过、听过、看过的一切，以文件形式存在手机本地目录，可全文搜索 |
| 术语表 / 词库 / 纠错映射 | 你纠正过的词和译法，下次识别与翻译时自动用上 |
| 去向账本 | 一张账：每一条数据去了哪里（没出手机 / 去了哪个云厂商 / 去了局域网哪几台设备） |
| 隐私档（四档） | 锁定 / 仅本机+逐段授权 / 仅文本上云 / 音频上云。默认大多是"仅文本上云"：录音不出手机，只有文字去云端润色翻译 |
| 路由三态 | 仅本机 / 自动 / 优先云端。决定识别在哪做 |
| 档位（四档） | 实时翻译的引擎组合：离线 / 混合（默认）/ 在线 / 一体化。混合 = 端侧识别 + 云端翻译 + 系统语音 |
| 零 Key | 用户没填任何云端 Key 时的状态。我们对"零 Key 能做什么、做不到什么"有一张诚实清单 |
| BYOK | Bring Your Own Key，用户自己带云厂商的 API Key |
| 待验证 / 待决策 | 待验证 = 需要真机实测才知道；待决策 = 需要有人拍板。都在附录 B |
| P0 / P1 / P2 | 优先级：P0 进 MVP，P1 进 v1.1，P2 进 v2 |

### 技术词

| 词 | 意思 |
|---|---|
| KMP / Compose Multiplatform | Kotlin 跨平台：一套代码同时跑 Android 和 iOS，界面也共享 |
| 端侧 / 云端 | 端侧 = 在手机本地跑模型；云端 = 调用第三方厂商 API |
| ASR | 语音识别（语音 → 文字） |
| TTS | 语音合成（文字 → 语音） |
| LLM | 大语言模型，用来润色、翻译、写纪要 |
| LID | 语种识别（判断这段话是什么语言） |
| VAD | 语音活动检测（判断有没有人在说话、一句话什么时候结束） |
| 声纹 | 用一小段声音算出"这是谁"的特征，用来判断"这句是我说的还是对方说的" |
| 润色 | 把识别出来的原始文字去口癖、加标点、纠错、按风格改写；规则是**不许改事实** |
| 快路径 / 慢路径 | 快路径 = 实时那一句，要在 1.5 秒内出译文；慢路径 = 对话结束后整段精修、写纪要、进知识库，**从不改动已经播过的内容** |
| sherpa-onnx | 端侧语音识别运行时（开源），我们用它跑 zipformer / SenseVoice / Paraformer 等模型 |
| zipformer / SenseVoice / Paraformer | 端侧识别模型：zipformer 管普通话 + 英文流式；SenseVoice 管粤语；川渝 Paraformer 管四川话 |
| 端侧 NMT / opus-mt | 手机本地跑的小型神经翻译模型（Helsinki-NLP 的 opus-mt，中 ↔ 英，每个方向约 80 MB，用 ONNX Runtime 跑；和音频编码 Opus 无关）。零 Key 时的默认翻译，两端一致 |
| 翻译三档 | 云端（用户自己的 Key 直连 qwen-mt / Claude Haiku / Gemini，有 Key 时首选）/ 端侧 NMT（默认离线档）/ 系统翻译插件（Apple Translation、ML Kit，v1.1 可选，设置里手动开） |
| ONNX Runtime（ORT） | 跑端侧模型的运行时；sherpa-onnx 和端侧 NMT 共用同一份，不装两套 |
| Apple Translation / ML Kit Translation | 苹果 / 谷歌自带的离线翻译；本方案只当 v1.1 的可选插件，MVP 不实现也不依赖；粤语都不支持 |
| qwen-mt / Haiku / DeepSeek… | 云端翻译与润色模型，需用户 Key |
| Koog | JetBrains 的 Kotlin AI 框架，我们只用它的"多厂商 LLM 执行层"，不用它的智能体功能 |
| Opus | 语音压缩编码，多机互传音频时用 |
| P2P / host / 说话方 / 听者 | 多台手机局域网直连，不经服务器；发起人手机当 host；说话方只发音频，听者各自在自己手机上识别翻译 |
| A2DP / HFP | 蓝牙耳机的两种模式：A2DP 音质好只能放不能录；HFP 能录但音质差。我们用手机麦克风录 + A2DP 耳机放 |
| PiP / Overlay | 画中画小窗 / 悬浮窗，Android 屏内字幕的两种载体 |
| MediaProjection / AudioPlaybackCapture | Android 抓取其他 App 播放声音的系统接口 |
| ReplayKit | iOS 的屏幕录制扩展，用来实验性地抓系统声音（审核有风险） |
| Liquid Glass | iOS 26 的玻璃材质设计语言；我们的 UI 全面走 Apple 风格，不用 Material 3 |
| Egress 门面 | 代码里所有"往外发数据"的唯一出口，顺手记账、按隐私档拦截 |
| expect / actual | KMP 里"接口在共享层声明、各平台各自实现"的写法 |
| Swift 注入 | 一些苹果 API 只有 Swift 能调（如 Foundation Models、画中画内容源），只能在 Swift 里实现，再注入给 Kotlin 共享层；v1.1 若启用系统识别 / 系统翻译插件也走这条路 |
