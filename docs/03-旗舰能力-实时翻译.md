# 03 · 旗舰能力：实时翻译（屏外面对面 + 屏内媒体）

> **这篇讲什么**：把面对面翻译和看视频翻译做成一张"模式矩阵"，说清楚每个模式给谁用、怎么触发、为什么不社死、多台手机怎么协作、延迟能到多少、iOS 上哪些做不了。
> **谁该看**：产品、开发。完整规格（协议字段、每个模式的交互步骤、失败处理、实测清单）在 [实时翻译场景矩阵-模块规格](实时翻译场景矩阵-模块规格.md) 和 [屏内翻译-模块规格](屏内翻译-模块规格.md)。

## 先看这个

1. **两条核心洞察**：① 输入和输出分开——麦克风永远是离说话人最近的那部手机，输出永远是听的人自己的耳机或转向对方的屏幕，两者不在同一条声学回路上，所以不需要回声消除、不需要半双工、不需要把手机递来递去；② 零社交摩擦——默认不举手机、不看屏幕、不外放、对方不碰我的设备，谁在说话自动判断，纠错靠耳机手势，所有外放功能都标黄当降级。
2. **一张四维矩阵**：输入源（麦克风 / 系统声音 / 屏幕文字 / 文件）× 输出形态（文本 / 语音）× 输出设备（本机 / 别的设备）× 交互形式（对话 / 单向）。屏外收敛成 12 个模式（M0–M12，M2 空缺），屏内 8 个（S1–S8）。
3. **MVP 只做 8 个**：M0 仅听、M1 耳听·面屏、M3 双屏对话、M4 速译卡片、S4 文件字幕、S8 外放旁听（两端），S1 系统字幕、S3 屏幕取词（Android）。
4. **多机架构一条规则**：说话的手机只发自己说话的音频（用声纹过滤掉别人的声音），每个听的手机用自己的模型或自己的 Key 做识别 → 翻译 → 语音。天然支持 N 个人各听各的语言。文本只在三种明确可见的情况下才在设备间传。
5. **延迟目标**：对方说完到译文进耳朵，中位数 1.5 秒以内、95 分位 2.2 秒以内（旗舰机、混合档、普通话 ↔ 英文）。这是目标不是承诺，第 10 周真机验收通过才写进文案；分项预算加起来其实是 1.25–2.45 秒。
6. **屏内的平台边界**：Android 能抓系统声音、能画中画显示字幕；iOS 抓不到其他 App 的声音，MVP 只做相册 / 文件 / 直链视频，其他 App 里正在播的视频属于"实验功能"，四项验证过了才做。

## 3.1 屏外与屏内

- **屏外**（麦克风听真实世界）：说话的人只管说，听的人戴上耳机。麦克风在手机上（朝向对方），译文从我的耳机（私密）或转向对方的屏幕出来。
- **屏内**（手机自己在播或存的视频）：输入从麦克风换成系统抓取的声音、文件解码的声音或屏幕上的文字；译文字幕浮在画面上，或译文配音进耳机；看完后字幕、纪要、生词进本地知识库。

**目标指标**（第 10 周验收通过后才对外写；度量口径：起点 = 对方一句话的句尾，终点 = 译文第一个音进耳朵）：
- 屏外：句尾 → 首音 P50 ≤ 1.5 s、P95 ≤ 2.2 s（iPhone 15 / 骁龙 8 Gen 2，混合档，普通话 ↔ 英文流式）；粤语 / 四川话走非流式模型，另列 P50 ≤ 2.2 s。30 分钟连续对话不断流；**耳机断开时绝对不外放**（实验室拔耳机脚本验收，泄漏窗口 ≤ 100 ms 是诚实边界）。
- 屏内：Android S1 冷启动 3 步 ≤ 8 秒，首条字幕落后画面 ≤ 3 秒；S4 十分钟 1080p 视频首条字幕 ≤ 5 秒，整片转写 ≤ 1/4 时长（旗舰机；手机上批量识别倍数预期 5–15×，第 13 周实测定）。
- 基线机（iPhone 12 / 骁龙 7 系）目标放宽到 ≤ 2.5 秒，达不到就关掉声纹、改成固定方向 + 滑动翻转。

**不做的组合及原因**：耳机上显示文本（不可能）；手表外放（音质差且公放）；网页对话（浏览器在 http 下拿不到麦克风，网页只能当听者）；"双方共用本机外放"（正是社死场景，只在 M3 里做黄标）；把第三方 App 的声音转播给朋友（版权）；视频通话 / 语音通话（不做通话录音，也不抓通话 App 的声音）；Auracast 蓝牙广播（iOS 26 不支持，Android 第三方需要特权，观察项）。

**实现上收敛为三条骨干**：单机骨干（M0–M7、S1–S5、S8）、P2P 音频 / 文本流骨干（M8–M12、S7）、本地网页骨干（M11-web）。三者共用同一条本机双速管线（3.5），多机只是把"麦克风"换成"远端音频流"，屏内只是换成"系统抓取流 / 文件解码流"。

## 3.3 升级阶梯与零社交摩擦

**升级阶梯**（每一级只多一个动作，永远能退回，切换时不重启音频）：
M0 仅听 →（翻转手机，姿态自动检测）M1 耳听·面屏 →（摘下耳机）M3 双屏。M1 →（对方愿意戴一只）M5 分耳；M0 →（对方也有 App）M8 双机；M0 →（只想说一句）M4；M0 →（对方没 App 但坚持要看字）M11-web。任何一级一键回 M0。

**触发：不举手机、不看屏幕**
- 物理前提：M0 用的是手机内置麦克风，手机得在**胸前口袋 / 手持胸前 / 挂绳**三种姿态之一（出门预热引导页会画出来）。裤兜隔着布料、朝向不对，能不能用要"三种姿态 × 三种噪声环境"实测（附录 B）；裤兜不达标，对外文案就只写"不用举手机、不用看屏幕"，不写"手机不出口袋"。
- **耳机按键**：只在会话进行中接管（App 播一条近乎静音的音轨成为"正在播放"的 App）：单击 = 开始 / 暂停，双击 = 跳过当前译文（对话模式 = 翻转上一句重译），三击 = 重播上一句。**待机时不接管**，你在听音乐时单击控制的还是音乐，这时入口是 Action Button / 磁贴 / 手表软开关。
- **姿态**：只在 App 在前台且屏幕亮着时生效——手机从水平 / 口袋转成竖直且屏幕朝外 → 自动进 M1 并点亮对方半屏；转回来 → 退回 M0。
- **待机档（出门预热）**：只驻留 VAD，识别和声纹模型卸载；触发后 1–2 秒重载并震动确认；与音乐、通话共存；有可见的常驻通知 / Live Activity，失效了会通知你。冷启动或被打断后需要"解锁点一下"，不假装能后台恢复。

**自动判向（零按键双向）**
- 会话只设 {A = 我, B = 对方} 两种语言，判向只做二分类。MVP 主判据：识别结果的文字是中文还是英文（zipformer 中英双语单模型，零体积零延迟——这也是 MVP 自动判向只支持中 ↔ 英的原因）+ 声纹投票（会话开始说一句注册"我"的声纹，每段算相似度）。
- 防抖：连续两句同一方向才切换；置信度低时沿用上一方向并在气泡上打"?"。纠错：气泡左右滑 = 翻转重译；耳机双击 = 撤回上一句反向重译；连续误判 3 次弹"固定方向"建议。
- 单向模式（M0 / M4 / M10 / M11 / 全部 S 系列）锁方向不跑判向，只过滤"我自己的声音"。
- 可选的语种识别包（whisper-tiny，98 MB）v1.1 再评估值不值得。

**礼貌开场与录音告知**
- 默认不外放开场白，首次触发只有耳机震动确认。录音告知由**对方半屏的礼貌卡**完成：翻转手机进 M1 时，对方半屏用对方的语言显示"我在用翻译听你说话，请正常说"+ 录音图标，3 秒后淡出成字幕区。
- **对方的声音默认不落盘，只存文字；知识库只存"我的语音"。** 德 / 法 / 日等地区首次使用弹一次合规说明，不强制阻断。

**隐蔽输出与对方视角**
- 耳语档（耳机输出限幅，按环境噪声自适应）；震动语义（开始监听 短-短 / 译文就绪 短 / 方向切换 长 / 掉线 长-长-长 / 听者"没听清" 双短），不用提示音；抬腕看最近两句 + 方向箭头。
- 对方看到的：M0——一个戴耳机、专注点头的人；M1——一块转向自己的字幕屏，礼貌卡 + 呼吸灯"我在听"+ 句尾打勾"收到了"+ 逐字译文（≥ 28 pt，最亮不锁屏），全程不碰我的手机；M5——一只干净的耳塞（一次性耳套）；M8 / M10——扫一次码、戴自己的耳机、手机放回口袋，一键"没听清 / 慢一点"→ 说话方手机震动，而不是开口打断。
- **对方拒绝**：礼貌卡常驻"我不用了，谢谢"按钮，按下用对方语言播一句退出语（唯一默认允许的一次外放，−6 dB），一键退回 M0 或结束会话并丢弃未落盘的缓冲。

## 3.4 多机架构规则：说话方只发音频，听者自己处理

**规则**：说话方只做 VAD + **"是不是我在说"的声纹门控** + Opus 压缩；听者在自己设备上做识别 → 翻译 → 语音合成。

为什么要声纹门控：饭桌上每个人的手机都会拾到所有人的声音，如果只靠 VAD 判"有没有人说话"就发，我的音频流里会混着对方自己说的话，对方会把自己刚说的话再识别、再翻译一遍播进自己耳朵。所以发送方只发"speaker = 我"的段，帧里带一个置信度供接收方再过滤一次。

由此得到：① 每个听者自选目标语言、引擎、Key，天然多语言；② 说话方不需要识别 / 翻译 / 语音模型和 Key，但**至少需要随包内置的声纹包（约 28 MB）和一句注册**；③ 默认设备间不传文本；④ 延迟关键路径上没有"等说话方识别完"这一步；⑤ 去向账本可以把"局域网出站"单列为"仅音频、仅对端设备、不经互联网"。

**主规则的三个显式例外**（文本才会在设备间传，每一个都在界面和账本里单列）：
1. 听者主动请求"提示"（自己没有源语言的识别模型），说话方选择附带自己的识别文字或译文；
2. 网页听者（对方没 App）：由我的手机识别翻译后推送文字；
3. S7 字幕共享：只共享本机已生成的原文字幕，不转播第三方视频的声音。

**听者用云端识别时，说话方必须知情**：听者选"在线档"意味着说话方的原声会被送到听者配置的云厂商。所以能力协商里带 `audioEgress = 本地 | 云端:<厂商>`，说话方界面常驻"N 位听者使用云端识别（百炼 / 火山）"；发起人开房间时可以设"仅端侧识别"，这时听者的在线档被禁用。

**角色**：Speaker（采集 + VAD + 编码）、Listener（解码 + 管线）、Host（发起人手机上跑一个局域网 WebSocket 服务器：管成员、广播控制消息、转发音频、缓存最近 10 秒音频；host 自己不识别不翻译，作为一个听者另起本地成员）。

**传输层**：主通道 = 同一 Wi-Fi（优先现场 Wi-Fi，其次我方热点）+ Bonjour / NSD 发现 + Ktor WebSocket，iOS ↔ Android 通用；蓝牙 BLE 只做无 Wi-Fi 时的 1:1 / 1:2 兜底（吞吐待实测）；同平台可用系统加速通道；不用 Multipeer（iOS 26 上不稳定）。Ktor 服务端在 iOS 上能跑 HTTP/1.1 + WebSocket 但没有 TLS（官方也不保证原生端服务器场景），所以**应用层端到端加密**（X25519 + ChaCha20-Poly1305，sender-key 模型：每个说话方的流密钥经成对通道分发，host 只转发密文）。热点：Android 用 LocalOnlyHotspot，iOS 只能引导用户去控制中心开。

**音频流要点**：16 kHz 单声道；Opus 20 ms 帧、Wi-Fi 24 kbps / 蓝牙 16 kbps；Wi-Fi（TCP）档关闭前向纠错（TCP 没有丢包，只有重传），蓝牙档开 FEC + 滑动窗口 + 重传请求；VAD 门控发送：只发有语音的段，开始前回溯 200 ms，结束后等 300 ms 发 `TURN_END`；抖动缓冲是给识别用的不是给扬声器用的：`TURN_END` 一到立刻排空、一次性喂给识别。

**控制消息**：握手、能力协商（识别语言 / 翻译语言对 / 语音语言 / 有没有云 Key / audioEgress / 想听的语言 / 要不要提示）、成员列表、房间策略、模式（圆桌 vs 讲座）、抑制（host 去重后回给被抑制的发送方）、句子开始 / 结束、静音心跳（每 2 秒，区分"没人说"和"掉线"）、提示请求 / 提示、反馈（→ 说话方震动）、时钟对齐（开始三次，之后每 30 秒）、心跳（2 秒，3 次没答判掉线）、断线续传（补最近 10 秒音频）、换密钥、结束会话。掉线重连指数退避 0.5 → 8 秒，超过 30 秒提示重新扫码。

## 3.5 双速管线与延迟预算

**快路径**（每一句硬实时）：音频源（本机麦 / 远端流 / 系统抓取 / 文件解码）→ VAD 门控 → 识别（流式部分结果 / 定稿）→ 分段（合并 < 400 ms 间隔的相邻段；远端流用 `TURN_END` 强制断句）→ 判向（声纹 + 文字脚本；单向和屏内关闭）→ 翻译（流式，半句提前翻）→ 语音合成（按标点切块）→ 播放队列（先进先出、提速、合并、压低）→ 输出（A2DP 耳机 / 双声道 / 屏幕 / 画中画 / 手表）。

每一步都有超时和降级：云翻译 1.5 秒没回 → 端侧 NMT（opus-mt）；云语音首包 0.8 秒没回 → 系统语音（无语音包时 Matcha）；云识别首包 1.2 秒没回 → 端侧流式。每一步有健康状态机：正常 → 慢（超时一次）→ 降级 → 探测（每 5 句对原档发一次影子请求）→ 恢复（连续 2 次正常就升回）。**语言对模型还没下载时**没有下一档：云翻译超时延长到 3 秒，超时后只这一句标"未译"并提示下载模型（约 80 MB / 方向），不改健康状态；这与平台无关，两端一致。

**慢路径**（会话结束时一次性执行；中途空闲 ≥ 20 秒只做规则层增量）：整段对话 / 字幕轨 + 风格 × 场景 + 词库 → 02 的 S0–S4 润色管线 → 精修文本、整段重译、纪要、章节、新词候选 → 知识库。**只补写字段，永远不改已经播过 / 显示过的内容。**

**端云组合（档位）**：

| 档位 | 识别 | 翻译 | 语音 | 句尾 → 首音 | 什么时候自动选 | 隐私档要求 |
|---|---|---|---|---|---|---|
| 离线 · 普通话 / 英文（流式） | 端侧 zipformer | 端侧 NMT（opus-mt 中 ↔ 英 int8，ORT，术语走 S0 替换 + 占位符回填） | 系统语音（无语音包时 Matcha 兜底） | **1.0–1.7 s**（目标；NMT 单句延迟待基线机实测） | 没网、网络差、用户选隐私、无 Key | 任意 |
| 离线 · 粤 / 川（非流式，只做 M0） | SenseVoice / 川渝 Paraformer + VAD，整段推理，没有半句提前翻 | 粤：零 Key 无（只繁简 + 粤语语音复述）；川：模型直接输出普通话 | 系统语音 | **1.6–2.5 s** | 同上 | 任意 |
| 混合（默认）· 普通话 / 英文 | 端侧流式 | qwen-mt（国内）/ Claude Haiku 4.5 / Gemini Flash-Lite | 系统语音 | **1.2–2.1 s**（半句提前翻开启后 P50 目标 ≤ 1.5 s） | 有网且 Key 可用 | ≥ 仅文本上云 |
| 混合 · 粤 / 川（M0） | 同离线 | qwen-mt（源语粤语） | 系统语音 | **1.8–2.9 s**（目标 P50 ≤ 2.2 s） | 同上 | ≥ 仅文本上云 |
| 在线（v1.1） | 云端流式识别（方言、语义断句） | 同上 | 云端语音（方言音色） | 1.0–2.0 s | 方言、要音质、对方说日 / 韩 / 欧语、网络好 | 音频上云（显式选） |
| 一体化（v2） | 端到端语音翻译模型 | 内置 | 内置 | ≈ 2.8 s | 用户显式选"懒人模式"，没词库没纪要 | 音频上云 |

**分项预算**（混合档、本机麦、流式）：静音判定 0.5–0.7 s + 半块 0.16 s + 终结解码 0.05 s ≈ 0.7–0.9 s；翻译首字 0.3–0.7 s；系统语音首包 0.1–0.6 s；蓝牙 A2DP 0.15–0.25 s。**合计 1.25–2.45 s**——这就是 P50 ≤ 1.5 s 只能是目标、必须第 10 周验收后再承诺的原因。

**MVP 语言对边界**：混合 / 离线档的端侧识别只覆盖 {普通话, 粤语, 四川话, 英文}，面对面自动判向只支持中 ↔ 英；对方说日 / 韩 / 欧语需要在线档 + Key（多语端侧识别包与更多 NMT 语言对 v1.1 评估），场景卡设置非中英语言时就会提示。

**半句提前翻译**（默认开，仅流式）：连续两次部分结果的公共前缀视为稳定，出现子句边界（逗号 / "然后 / 但是 / because / and"）或 1.5 秒没变就送翻译并标"临时"；定稿后只翻增量；改动超过 15% 才整句重译替换字幕。

**打断与压低（软半双工）**：耳机模式输入是内置麦、输出是 A2DP，天然全双工没有回灌，识别在播放期间持续工作，**不开回声消除**。对方插话超过 300 ms：100 ms 内把译文压低 12 dB，对方说完 500 ms 后恢复；插话超过 1.5 秒：丢掉剩余队列并标"未播完"。我方开口：立刻停止并把没播完的译文转成屏幕文字。积压 ≥ 2 句语速 1.15–1.25×；≥ 4 句合并并标"已合并"。

**发热与电量四级阶梯**：正常 → 略热（关半句提前翻，少 30–50% 翻译调用）→ 严重（识别降线程、关声纹和判向改固定方向、语音强制系统、字幕 5 Hz；**不在发热时加载 237 MB 的粤语模型**）→ 危急（暂停语音只显示字幕，多机模式通知 host）。目标：混合档 1 小时 ≤ 15% 电量（待验证）。

## 3.6 多人多语言

- **拓扑**：星型，发起人 = host；1:1 直连同协议，第三台加入时自动升级星型。
- **配对**：同一 Wi-Fi 的 Bonjour 列表（零扫码，仅 M8 且需对方确认）；二维码 `scenenote://join?...`（带公钥和盐；不同网时同一码附 Wi-Fi 配置）；**M10 / M11 加入必须校验二维码盐值或房间 PIN**，避免同一咖啡馆 Wi-Fi 的陌生人静默加入收听。
- **host 退出**：热点场景 host 一走就散会（界面明示"发起人请勿离开 / 锁屏"）；现场 Wi-Fi 场景由最早加入的人自动接任。
- **同源去重**：饭桌上每人一机，所有麦克风都拾到同一个说话人——靠发送侧声纹门控（只发自己的段）+ host 侧同源去重（同一时间窗多路相同内容只保留一路），被抑制的发送方收到"抑制"消息。
- **带宽**（Opus 24 kbps + 帧头加密 ≈ 30 kbps / 流；声纹门控后只有说话人的手机在发）：1:1 → 30 / 30 kbps（蓝牙也够）；4 人 1 路说话 → host 上行 30 / 下行 90 kbps；8 人 2 路抢话 → 60 / 420 kbps（iOS 热点上限约 5 台待验证，超过 6 人用现场 Wi-Fi）；讲座 1 → 20 人 → 30 / 600 kbps（host 强制 5 GHz）。听者每路识别占一个大核 15–25%。
- **听者侧降级**（听者主动请求；不请求就永远只发音频）：D0 有识别 + 翻译 + 语音 → 完整本地管线；D1 没有源语言识别 → 请求说话方附带转写；D2 只有语音合成 → 请求说话方按听者语言翻译；D3 网页听者 → 同 D2，语音用浏览器自带合成；D4 说话方也没能力 → 听者只收原声并提示"下载离线模型（约 70–230 MB）或填 Key"。说话方界面能看到"N 位听者需要我帮忙转写"和由此增加的算力 / 费用。

## 3.7 对方没有 App 怎么办

按对方门槛从低到高，外放路径都不进主入口：
1. **M1 / M3 / M4**（零门槛，P0）：对方只看我的屏幕；
2. **M5 借一只耳机**（P1）；
3. **M11-web 网页字幕**（P2，最后兜底）：优先同一 Wi-Fi——对方扫码打开 `http://<我的IP>:8080`，不用断自己的网；没同网才引导我方热点。页面 < 100 KB 全内联，大字号、深色、可翻转、"没听清"按钮，首屏"点击开始收听"解锁浏览器语音。网页只做听 / 看，说话还是对着我的手机；
4. **Auracast 蓝牙广播**（P3 观察）：Android 16 只引导系统"音频分享"，iOS 不可用；
5. **AirDrop / Quick Share 对话卡片**（会后）。

## 3.8 屏内：平台诚实矩阵

每条路径有一个"等级"，决定商店描述和帮助页怎么写：**CORE** 可写进商店描述；**ANDROID_ENHANCED** 写"Android，且被播放的 App 允许时"；**IOS_EXPERIMENTAL** 写"实验功能，可能随时调整"；**FALLBACK** 只在帮助页出现。**禁止"Beta 即将推出"这类提前承诺。**

| 路径 | Android | iOS |
|---|---|---|
| 抓其他 App 的声音 | **可行**：MediaProjection + AudioPlaybackCapture；每次会话系统弹窗；Android 15+ 状态栏有 chip、锁屏自动停止（披露页提前说明） | **抓不到**；ReplayKit 广播扩展 + 画中画字幕属**实验层，四项验证后才做**：需点"开始直播"3 秒倒计时、红色指示常驻、只能一个画中画、窗内不能交互 |
| 被播放的 App 允不允许抓 | Netflix / Spotify **不允许**（公开来源）；YouTube / Twitch / Prime / VLC 为社区报告待复核；抖音 / B 站 / 腾讯视频 / 爱奇艺 **待验证**（国内长视频大概率不行）。**探测**：抓 2 秒声音接近 0 且系统说"有媒体在播" → 判定被拒，诚实提示并自动换 S3 / S8 | DRM 平台视频黑屏，音频待验证 |
| 字幕载体 | 画中画（免权限、最顶层、全系统同时只能一个——回桌面时 YouTube 自己的画中画会顶掉我们的，这时自动切通知栏最近一句或提示开悬浮窗；画中画内字号只允许 14 / 18 sp）→ 悬浮窗（需权限，小米 / OPPO / vivo 还需"后台弹出界面"）→ 无画面（耳机语音 + 通知最近一句） | 画中画承载纯文字是 **App 审核灰区**，有翻译 / 计时器类画中画被拒的先例 |
| 屏幕文字 OCR | **可行**：复用 S1 的投屏授权截帧 + ML Kit（中日韩 + 拉丁，+12–16 MB）；截帧前先隐藏自己的画中画，否则会把自己的译文再翻一次 | **不可行**：只能截图 / 相册图片 OCR |
| 网页视频 | 跟随 Chrome 是否允许抓（待验证） | **不可行**（引导用平台 App 或系统实时字幕） |
| 文件 / 相册 / 分享 / 直链 | 可行（不落盘解码；HLS 直链先拉分片） | **可行**（直链 MP4 可以；**HLS（m3u8）MVP 标不支持**——系统的音频处理接口不支持 HLS，"先下载再处理"也走不通） |
| 耳机配音 | 可行：句级压低替换 / 纯混音 / 静音原声三种策略 | 实验：能压低别人的声音，但控制不了别人的音量 |
| 外放旁听（S8） | 可行（= M0 媒体调参：只对电视 / 电脑 / 别人手机，**不适用于本机正在播的视频**——本机外放 + 本机麦会触发回声路径，而且公放本身就是社死） | 可行（同左） |

**Android S1 流程**：磁贴"屏内翻译"或 App 内"翻译我正在看的视频" → 系统投屏弹窗 → 前台服务 → 画中画字幕条"正在聆听…" → 2 秒探测通过后出第一句灰字。首次额外插入**显著披露页**（抓取应用音频、是否离开设备、Key 去向、锁屏停止、状态栏 chip）和**载体选择页**。锁屏停止后解锁弹低打扰通知"点击恢复"，重新走系统弹窗（躲不掉，诚实告知）。

**S4 文件字幕（两端一致，"默认不问问题"）**：相册 / 微信视频 → 分享 → 选场记 → 自动开始；App 内屏内 Tab → 选视频（不申请相册权限）；剪贴板里有直链 → 提示"翻译这个链接？"；处理过的视频打开即播。语言自动检测（前 5 秒），场景 / 风格沿用上次，目标语 = 系统语言；播放器顶部的语言芯片改了就从当前位置重翻。**零 Key 的本地原文轨只覆盖普通话 / 英文 / 粤语 / 四川话**；日 / 韩 / 欧语视频要配置 Key（多语端侧识别包 v1.1 评估），否则入口就提示。

**iOS 的诚实说明**（首次进入屏内入口显示）：相册 / 文件 / 分享来的视频完整支持；其他 App 正在播的视频需要通过"屏幕录制"获取声音并用画中画显示字幕，属实验功能；都不行时可以把手机放电视旁用"外放旁听"。MVP 的显式降级步骤：在视频 App 里保存到相册 / 存到文件 / Safari 下载 → 分享给场记 → S4。iOS S1 进 v1.1 的四项前置验证：① 画中画承载纯字幕的审核态度（TestFlight 探一次）；② Netflix / Apple TV+ 的声音是否被静音；③ 画中画 + 扩展连续 30 分钟的内存与稳定性；④ 扩展与主 App 之间的通信延迟。

## 3.10 和 App 其他能力怎么咬合

实时对话和屏内观影的会话结束时触发慢路径，复用 02 的润色管线、术语表、风格 × 场景提示词、卡片渲染、本地知识库、去向账本和 Key 保管；本章只新增了档位预设、模式定义、P2P 骨干和字幕产物。"实时对话 / 观影 → 转写 → 润色 → 知识库 → 词库 → 下次翻译更准"的完整闭环见 04 的 4.9。
