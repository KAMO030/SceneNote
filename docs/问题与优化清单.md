### A. 音频与实时管线

**B1 · 说话了却"跟没说一样"**（09-17 12:01 / 16:56）
- 你的原话：「你 adb 抓下日志看看为什么我说话了但是没有被翻译出来和我没说话一样」「现在直接打开"面屏"扬声器里直接播放测试的音频并且没有被正确翻译」
- 根因：采集源用的是 `MediaRecorder.AudioSource.VOICE_RECOGNITION`，vivo（OriginOS）对这个源做了重度降噪 + 门限，人声只剩 −45 ～ −60 dBFS，VAD / zipformer 判不出来。同一声源换 `MIC` 高 20 dB 以上（−15 ～ −25 dBFS）。
- 改法：[AndroidAudio.kt:56](../shared/src/androidMain/kotlin/dev/scenenote/audio/AndroidAudio.kt) 采集源改 `MIC`（自检的 `MEASUREMENT` 仍走 `UNPROCESSED`），保留每 5 s 一条的 `SN/mic` 电平日志。
- 验证：V2436A 真机，同一段样本 —— 换源前「勉强出字、后半段错乱」，换源后「昨天是 MONDAY」→ "Yesterday was Monday." ✅
- 提交：`2882bd7`

**B2 · 识别叠字**（09-17 17:11）
- 你的原话：「现在声音转文字有问题会出现一个字重复连在一起出现两次」
- 根因：不是管线问题——把麦克风原始 PCM 落盘再回喂，得到一模一样的叠字，是流式 zipformer（int8 双语）对近讲 / 拖长音本身会重复吐字；换 `modified_beam_search` 不解决且更慢。原实现的两个短板让定稿救不了场：定稿等的是 Silero VAD 自己弹的段（连续讲话要等 4–7 s，还会把上一句 id 配到下一句音频上）；草稿一到就翻译送 TTS，定稿来了也不再重译。
- 改法：定稿改用**本句自己的音频**在句尾立刻跑（3 s 的话约 100 ms 出 rev1）；草稿仍立刻上屏，但翻译最多等 1.2 s 让定稿赶上。见 [SherpaAsrEngine.kt](../shared/src/commonMain/kotlin/dev/scenenote/asr/SherpaAsrEngine.kt)、[FastPath.kt](../shared/src/commonMain/kotlin/dev/scenenote/live/FastPath.kt)。草稿层的去叠见优化 O2。
- 提交：`2882bd7`

**B3 · 仅听里译文没播完**（09-17 17:11）
- 你的原话：「仅听里如果对方一直在说话，翻译的音频会出现没播完的情况」
- 根因：软半双工规则——对方说话时译文压低 12 dB、1.5 s 后丢弃剩余队列。这是给"对方插话"设计的，仅听（讲座 / 视频）对方从头说到尾，每句译文都被砍到 1.5 s。
- 改法：[FastPath.kt:307](../shared/src/commonMain/kotlin/dev/scenenote/live/FastPath.kt) 仅听（`SIMPLEX_IN`）不再把对方说话当插话；[PlaybackQueue.kt:58](../shared/src/commonMain/kotlin/dev/scenenote/live/PlaybackQueue.kt) 补上积压规则（后面还排 ≥ 2 句时语速 1.2×）。M1 / M3 对话模式保持原行为。
- 提交：`2882bd7`

**B4 · 外放时译文被自己听回去**（09-17 23:18 → 23:40 回滚）
- 你的原话：「翻译后输出时的声音在手机外放的情况下会被再次变成输入音频」；修完你说「那还是改成之前那样会被再次变成输入音频吧」
- 根因：规格 §6.2 要求"播放后 800 ms 麦克风门控 + AEC"，代码里只落地了文本相似度过滤（相似度 > 0.8 才丢）。实际拾回来的往往是残缺的（"Yesterday was Monday" 听成 "WAS MONDAY"），过不了阈值就漏过去，然后被翻译、再播、再拾回。
- 一度的改法：外放路由下播放期间把采集帧换成静音送给识别，播完再保持 800 ms；耳机不门控。
- **你的决定**：门控期间对方的话也听不到，等于外放只能半双工，你要求改回去。现已撤掉门控，只保留相似度过滤。要真做全双工外放得走 `VOICE_COMMUNICATION` + 系统 AEC，而这台 vivo 连 `VOICE_RECOGNITION` 都被压了 20 dB，风险高，没动。
- 状态：🔁 已回滚

**B5 · 面屏分不清我方 / 对方，语言要在设置写死**（09-17 18:19）
- 你的原话：「面屏时没办法区分对方与我方的声音；没办法自动识别说话人的语言，不应该在设置里帮死我的语言与对方的语言」
- 根因：MVP 判向是二分类（预设 {我 = A 语言，对方 = B 语言} + 脚本主判据 + 声纹投票）。对方说日语时中英流式模型只吐乱码汉字，脚本一看是中文就判成"我"；声纹只存在进程内，重开 App 就得重新隐式注册。
- 改法：① 对方语言可以选「自动」——定稿引擎 SenseVoice 自带语种识别（中 / 英 / 粤 / 日 / 韩），每句定稿的语种落在我的语言家族之外就判为对方，并学成本会话的对方语言，礼貌卡 / TTS 语言跟着换；② 「我」的声纹持久化到设置（`meVoice`），下次进对话页第一句就能靠声纹分人。
- 验证：真机 M1，Mac 放日语再放韩语 —— `lid → OTHER ja→zh-CN`「今はどこですか？」→「你现在在哪里？」，切韩语后 `other=ko`。
- 边界（当时说明过）：「我的语言」还是要设（它是译文的目标）；自动识别只覆盖 SenseVoice 的五种语言；日 / 韩**实时草稿仍是乱码**，靠句尾定稿替换；两人说同一语言时只能靠声纹。
- 提交：`2882bd7`

**B6 · 双屏说话没反应**（09-17 19:38）
- 你的原话：「但是现在双屏说话没反应也不翻译」

**B10 · 视频翻译没被正确翻译**（09-18 13:17）
- 你的原话：「并且视频翻译功能未正确被翻译」

- 验证：新增 `SubtitleLangTest`；真实离线模型下多行输入行数不变、逐行结果与单句一致。
