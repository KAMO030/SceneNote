# 10 · MVP 范围与路线图

> **这篇讲什么**：MVP 18 周每周做什么、第 4 周和第 10 周两道关卡验什么、验不过怎么砍；v1.1 和 v2 各做什么；总共多少人多少周。
> **谁该看**：全员。文末附原始的逐周技术清单（给开发对账用）。

## 先看这个

1. **MVP = 18 周、6 人，口号"五张卡，两条直线，去向可见"**。五张卡：面对面对话、屏内字幕、会议、口述成稿、方言家庭。两条直线：录音线（入口 → 场景 → 录音 → 整理 → 产物 → 分享）和实时线（触发 → 快路径 → 听 / 看 → 慢路径入库）。
2. **两道关卡**：
   - **第 4 周**：在基线机（iPhone 12 / 骁龙 7 系）上实测各模型的速度、内存、耗电，定内存分级；离线档能不能做到 2.5 秒内出译文。不过 → 基线机默认关声纹改固定方向、默认用 greedy 解码。
   - **第 10 周**：旗舰机上混合档中英对话 P50 ≤ 1.5 s / P95 ≤ 2.2 s；粤语仅听 P50 ≤ 2.2 s；30 分钟不断流；拔耳机 100% 不外放；三种姿态 × 三种噪声下的判向准确率；待机 8 小时电量。不过 → 关半句提前翻、文案不写延迟数字；手动翻转超过 25% → 判向默认固定方向；姿态误触发超 5% → M1 默认手动；裤兜不达标 → 文案只写"不用举手机、不用看屏幕"。
3. **取舍纪律**：MVP 只有两条判断标准——录音线"三个录音场景能否一按之后 10 分钟内交出一份能分享的稿子"（有 Key = 模板成稿，零 Key = 规则整理稿，都必须能分享）；实时线"M0 / M1 / M3 / M4 和 S4 / Android S1 能否在旗舰机上达标且拔耳机不外放"。不直接服务这两条的功能一律后移，哪怕实现成本很低。
4. **首发方言必须同时有粤语包和川渝包**，否则"方言家庭"对四川家庭是空承诺；上海话 / 闽南语 MVP 只走云端并在卡里隐藏。
5. **人力**：2 KMP/Compose、1 音频与实时管线、1 iOS 原生、1 Android 原生、1 全栈兼 CI。**只有 4 人时**：Android S1 / S3 和 M4 移到 v1.1，屏内只交付 S4 / S8；或者维持范围延到 24 周（附录 B 待决策 10）。
6. **总计**：MVP 18 周 + v1.1 10 周 + v2 14 周 = 42 周。比拆分前 v1 方案（4 人 30 周）多 2 人 12 周，增量全部来自旗舰屏外三期和屏内三期。

## v1.1（第 19–28 周）："多机私聊 + 屏内增强 + 数据层深化 + 零 Key 成稿"

- **屏外 P1**：M8 双机私聊、M9 双机字幕、M5 分耳、M12 抬腕字幕；P2P 传输层第一版（同网发现 + 二维码 + 热点引导；Opus 双端绑定；端到端加密；说话方声纹门控 + host 同源去重；听者上云可见；时钟对齐、断线续传、反馈震动）；在线档（云端识别 + 云端方言音色）。**立项前先做技术验证 + 安全评审**：加密库绑定、Ktor 服务端在 iOS 真机的稳定性、局域网权限弹窗、锁屏存活、iOS 热点上限、Opus 互通。
- **屏内 v1.1**：Android S2 耳机配音、悬浮窗载体、OCR 自动刷新与框选、锁屏恢复；两端 S5 文件配音；术语表回流屏内；看课程·笔记 / 看剧·口语子卡；**iOS S1 实验层（四项验证通过才做）**；iOS HLS 分片自取评估；多语端侧识别包评估；语种识别包是否值得评估。
- **端侧引擎插件与语言对扩展**：评估并按需实现 `AsrEngine` 下的系统识别插件（iOS SpeechAnalyzer / SpeechTranscriber、SFSpeechRecognizer；Android SpeechRecognizer）与 `FastTranslator` 下的系统翻译插件（Apple Translation、ML Kit Translation），一律设置里手动启用、默认关闭，不改变 sherpa-onnx + `core/nmt` 的默认路径；评估更多 opus-mt 语言对（en↔ja / en↔ko / 欧语等，按可用模型逐对）与更大 / 蒸馏版中英模型；评估 TTS 是否统一到 sherpa-onnx（附录 B 待决策）。
- **v1 遗留的 v1.1 项**：讲座旁听卡；课堂 / 采访卡；**本地大模型润色（Llamatik + Qwen3.5-2B，只在慢路径）**；标点包；方言大包；火山引擎作第二云端；个人风格示例学习；语料回响；`.scene` 深链与面对面二维码；Live Activity + 后台起录；连续记录与周报小组件；手表录音回传；夜间精修；周报 / 一年前的今天 / 生词复习；系统模型完整风格支持；iCloud Drive 与 SAF 云盘目录；风格档案导出。
- 人力：6 人 10 周；4 人则 14 周并把 M5 / S2 / 悬浮窗顺延。

## v2（第 29–42 周）："多人多语 + 全入口 + 社交"

- **2027 观察项**：Wi-Fi Aware 跨平台、Auracast 第三方广播、App Clip 入会、iOS 27 LE Audio 开放、Android 16 音频分享是否含第三方媒体流。
- 人力：6 人 14 周。

## 附：原始逐周技术清单（开发对账用，措辞未简化）

### MVP（第 1–18 周，6 人）："五张卡，两条直线，去向可见"

《矩阵规格》§13.1 单独估算屏外 P0 需 8–10 周，v1 录音 MVP 本身 14 周，屏内 P0 未估周数——三者不可能压进 14 周，v2 草稿把屏外 P0 交互压进"周 8"一周、屏内 P0 压进两周是排期错误。本节按角色 × 周重排为 **18 周**，在周 4 与周 10 设 go/no-go 门并写出 no-go 时的范围；**分期以本节为准**，《矩阵规格》§13.1 与《屏内规格》§10.1 的相对周数已被本节覆盖。

- **周 1–2**：工程基线（Kotlin 2.4.0 / CMP 1.12.0 / Decompose / Koin / SQLDelight + androidx 驱动 / Ktor + Egress 门面（含 `lan` 类目预留））；`AudioSource` 双端（平台 AAC 落盘）+ **`RouteManager` 双端（输入强制内置麦 + A2DP 铁律、不加 `.defaultToSpeaker`、`routeEvents`、EarbudLost 在回调内同步 stop + flush、Android `ACTION_AUDIO_BECOMING_NOISY`、硬件缓冲 ≤ 40 ms、prime）**；Transcript IR + `segment_revisions` + `polish_revisions` + `conversations / utterances / subtitle_tracks / subtitle_cues` 表；本机 Vault 目录读写 + SQLite 重建（不接云盘）；`models.json` 内置 + Background Assets / PAD 桥 + `.sherpa-pack` 手动导入；CI 两条 workflow + 包体积门禁（计入项与 250 MB 阈值）+ **延迟基准脚本骨架（起点 = VAD 语音结束时刻减静音阈值回推的句尾 / 远端流 `TURN_END`；本机终点 = TTS 首帧写入 `AudioSink`；实验室终点 = 麦克风旁录耳机出声；两口径差值按实测 A2DP 回环补偿）**；**Android 屏内 FGS 演示视频与 Play 声明草案（前置任务）**。
