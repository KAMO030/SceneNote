# 演示视频 · 操作脚本

iPhone 17 Pro 模拟器录屏，约 100 秒，一镜到底后剪。全程不联网、不连云端翻译：识别、翻译、纪要都在本机。
覆盖六件事：**面对面对话（仅听 / 面屏 / 双屏）→ 速译 → 视频字幕 → 会议纪要 → 主题色 → 界面语言**。

故事线：在国外问路 → 给对方看一句大字 → 回来给相册里的视频配字幕 → 开个会出纪要 → 顺手换个主题色、换个界面语言。

### 相册里的演示视频

字幕那一幕要有一条**带英文人声的视频**在相册里。用模拟器自带的冰岛瀑布照片做一条 13 秒竖版短片：

```bash
say -v Samantha -r 165 -o vlog.aiff "[[slnc 900]] This is the most famous waterfall in Iceland. [[slnc 950]] It rains here almost every day. [[slnc 950]] You can walk right up to it. [[slnc 950]] Do not forget your raincoat. [[slnc 1000]]"
ffmpeg -y -loop 1 -i IMG_0005.JPG -i vlog.aiff \
  -filter_complex "[0:v]crop=1126:2002:1267:0,scale=1080:1920,zoompan=z='min(zoom+0.0009,1.2)':d=420:x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)':s=1080x1920:fps=30,format=yuv420p[v]" \
  -map "[v]" -map 1:a -c:v libx264 -crf 20 -c:a aac -t 13.5 -movflags +faststart vlog.mp4
xcrun simctl addmedia <udid> vlog.mp4
```

句子要挑端侧模型译得干净的：专有名词（Skogafoss）会被识别成乱码，「It is sixty meters high.」会被译成「高60米，我从这里走」——都换掉。上面这四句实测中英都稳。
相册里有多条视频时**最新的排在第一个**（左上角），选它。

### 时序：工具驱动的坑

用 MCP 的模拟器工具点按时，**发出命令到真正点下去有 3–6 秒不等的延迟**，所以凡是「点一下 → 马上说话」的地方都要留够提前量：

- **连续听的页面**（仅听 / 面屏 / 双屏 / 会议）：先点「开始」，再在**前台** `sleep 2 && afplay ...`。前台跑最稳。
- **速译的按住说话**：长按会把工具调用堵住，只能先安排声音再按。实测「后台任务里 `sleep 9 && afplay quick.aiff`，紧接着发 9 秒长按」正好落在按住区间里；提前量给到 4 秒会只录到句尾（「的车票。」），音频单元要 ~2 秒才开始进声。
- 后台放音要用**会跨轮次存活的后台任务**；`cmd &` 这种在工具调用结束时会被杀掉，表现为「按住了但什么都没听见」。

## 录制：分段录，别录一镜到底

一镜到底录了两次都废了：中途 App 被外部重装过（见下），而且工具调用之间十几秒的空档会让原始文件长得没法收拾。**一幕一个文件**，录完立刻看一眼，坏了只补那一幕。

还有个坑：`simctl recordVideo` 的时间戳只在画面变化时推进，**最后一次画面变化之后的静止画面不会进文件**。所以结尾停在一张静止页（纪要、字幕成品、大字卡）的那几幕，录完的文件会在最后一次变化处就截断——要么录完再点一下（切个分段、来回切 译文/原文）制造帧，要么后期用 `tpad` 把尾帧续上。本次是两招都用：成品页单独补录（F / G 两段），大字卡用 `tpad` 续 3.2 秒。

## 后处理

先统一转成恒定 30 fps 并缩到 588 宽：

```bash
ffmpeg -i takes/A.mp4 -vf "fps=30,scale=588:-2" -c:v libx264 -crf 18 -an cfr/A.mp4
```

找剪辑点不用肉眼翻：让 ffmpeg 把「画面变了」的时刻打出来，再在每个时刻后面留 3–5 秒：

```bash
ffmpeg -i cfr/A.mp4 -vf "select='gt(scene,0.012)',metadata=print:file=-" -an -f null - 2>/dev/null   | grep -o "pts_time:[0-9.]*" | cut -d: -f2
```

然后每段切成一个文件再 concat（比一条大 filter_complex 好调）。切主题色那一段用 `setpts=PTS/2.5` 提速，六个色板点下去才跟得上节奏；大字卡那段用 `tpad=stop_mode=clone:stop_duration=3.2` 把尾帧续住：

```bash
ffmpeg -ss 37.0 -to 63.5 -i cfr/E.mp4 -vf "setpts=PTS/2.5,fps=30" -c:v libx264 -crf 20 -an -r 30 seg/18.mp4
ffmpeg -f concat -safe 0 -i concat.txt -c:v libx264 -crf 23 -preset slow -pix_fmt yuv420p -an -movflags +faststart demo.mp4
ffmpeg -ss 1.2 -i demo.mp4 -frames:v 1 -q:v 3 poster.jpg   # 封面取场景页那一帧
```

放到 `docs/介绍页/video/demo.mp4`（和 `poster.jpg`），页面自动从占位卡切成播放器。线上 artifact 单文件上限 15 MB，本次 1.4 MB。

## 录之前先确认：App 没被重装过

模拟器上的 App 一旦被重装（Xcode 跑一次、`simctl install` 一次都算），**数据容器会整个换掉**：语音包、资料库、设置全没了，界面会变成「本机识别不可用 · 去下载语音包」。录制当天就被这么清过一次，645 MB 语音包得重下（好在从 HF 镜像下只要一两分钟）。

开录前扫一眼容器还在不在：

```bash
cd ~/Library/Developer/CoreSimulator/Devices/<udid>/data/Containers/Data/Application
for m in */.com.apple.mobile_container_manager.metadata.plist; do
  [ "$(plutil -extract MCMMetadataIdentifier raw "$m")" = dev.scenenote.app ] && du -sh "$(dirname "$m")"
done
# 600 MB 以上才是语音包都在
```

被清过就要重来一遍：设置 → 管理语音包 下载**静音检测 / 中英识别 / 多语言识别 / 中·粤译英 / 英译中**五个包，再把 译文朗读 关掉、主题色调回粉色、界面语言调回中文。

另外首次会碰到两个系统弹窗，会串进画面里，**开录前先各触发一次**：视频字幕页的「想从 CoreSimulatorBridge 粘贴」、会议停止时的「想给你发送通知」。

一版录制时以为「面屏切双屏会崩」，其实是那段时间 App 正在被反复卸载重装（见上），碰巧撞在那一下。后来在干净环境里按同样路径跑了三遍都没事，双屏这一幕已经补录进片子。
