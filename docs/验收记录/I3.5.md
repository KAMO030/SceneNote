## 3. 决策与取舍

- **贪心而非 beam**：手机上单句 ≤ 0.3 s 优先；beam 2–4 需要按 batch 重排 KV cache，留作 v1.1 评估项（附录 B 49）。
- **英 → 韩暂无端侧包**：opus-mt-en-mul 不含 kor；唯一的 Marian 模型 opus-mt-tc-big-en-ko（HF 上三家 int8 导出都 > 370 MB）实测全部输出 `<unk>`——Helsinki 仓库的 vocab.json 只有韩语目标词表（"sepvoc" 模型转换坏了，英文 piece 全对不上），上游就不能用。零 Key 时提示「这对语言暂无离线翻译」，有 Key 走云端。
- **中转**：日 / 韩 ↔ 中、中 / 粤 / 韩 → 日 没有直连模型，经英语两步（时延翻倍），路由标签写成 `ja-en→en-zh:cmn_Hans` 进账本与诊断。实测：「この価格は高すぎます。もう少し安くなりませんか。」→「价格太高了，你为什么不便宜一点？」；「这个价格太贵了，能不能便宜一点？」→「これは高すぎる。安くしてもらえませんか。」；「안녕하세요, 만나서 반갑습니다.」→「嗨，很高兴见到你。」。
- **第三方导出**：FuguMT 的 ONNX 来自 Kadonox（非官方，109 次下载），sha256 锁死；仓库消失时要另找镜像或自己用 optimum 导出后托管。
- **不同 ORT 内核的近似平局**：关预打包（LOW / MID 机型）时 MatMulInteger 走另一套 int8 核，logits 差 0.1–1，近似平局的词会变（"Why don't you get a little cheaper?" ↔ "Wouldn't it be a little cheaper?"），都对；测试参考按 Python 默认会话（预打包开）生成、Kotlin 测试用同样选项。
- **术语表**：端侧路径暂不注入术语（占位符回填对 Marian 不稳），云端路径不变；成稿阶段的术语替换仍由 S0 规则层负责。
- **常驻**：每方向 ≈ 170 MB（LOW / MID 不预打包；HIGH 预打包换 ≈ 1.5× 解码速度）；面对面对话两方向同驻；会话结束即卸载，进页预热。
- **模型改写而不是换模型源**：项目没有自己的分发渠道（无 git remote / GitHub Release），Xenova 仓库原样下载后本机改写；改写产物与原文件并存（多占 93 MB 磁盘），删除包时一起删。
- **短句幻觉**：opus-mt en-zh 对 "The day after tomorrow." 这类短句会续写（"后天，我再给你打电话"），是模型训练数据的毛病，贪心 / beam 都有；实时场景里句子多为完整口语句，影响有限，记入附录 B 50。
- **许可**：zh-en 基模型 CC-BY-4.0（署名义务待法务）；其余五个 Apache-2.0（HF cardData 2026-09-18 核实）。

## 4. 需要你来测的

1. **vivo 上走一遍真实下载**：设置 → 语音包 下载「中译英」「英译中」（各 108 MB，国内走 hf-mirror；本次真机数据是 adb 推进沙盒的文件）；看下载页进度与 sha256 校验。
2. **iPhone 真机**：不填 Key 进「仅听」喂 `test0.wav`；另看 Locked 隐私档下翻译是否仍走端侧；PSS 与首句等待。
3. **对话模式两方向同驻 + 声纹 + zipformer** 跑 10 分钟的发热与降频（附录 B 49 的 spike）。
4. 日 ↔ 中 中转链路：下载「日译英」+「英译中」，把对方语言设成日语，看两步时延是否可接受（桌面两步 25–32 ms，手机预计 0.7–1 s）。
5. 有 Key 时断网：确认 1.5 s 超时后落到端侧，状态胶囊显示「离线」而不是「无翻译」。
