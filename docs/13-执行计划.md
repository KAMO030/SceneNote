# 13 · 执行计划（精简 MVP · 你 + Claude · 双端同步）

> **这篇讲什么**：把 10-路线图（6 人 18 周）压成"1 位真机操作者 + Claude 写代码"的可执行版本：范围砍到"实时线优先精简版"，按里程碑而不是按周推进，每个里程碑有交付物、验收标准、以及你要亲手做的真机事项。
> **决策来源**：2026-09-17 拍板——直接在本仓库写代码；人力 = 你 + Claude；Android / iOS 双端同步交付；MVP 取"实时线优先精简版"。
> **版本来源**：repo1.maven.org / dl.google.com 的 maven-metadata 与 GitHub Releases（2026-09-17 核对），组合以 JetBrains 官方 KMP-App-Template 为准。

## 先看这个

1. **范围**：旗舰屏外 **M0 仅听 / M1 耳听·面屏 / M3 双屏对话 / M4 速译卡片**（中 ↔ 英自动判向 + 粤 / 川单工 M0）+ **会议卡**（录音线最小闭环）+ 屏内 **S4 文件字幕 / S8 外放旁听**（双端）+ **Android S1 系统字幕**（关卡 B 之后）。
2. **延后到 v1.1**：口述成稿卡、方言家庭卡、`.scene` 导入导出、P2P（M8+）、手表、Widget（只留最小入口）、Koog、Android S3 OCR、Live Activity。
3. **两道关卡保留**：关卡 A（= 路线图第 4 周）基线机模型基准与离线档 M0；关卡 B（= 第 10 周）旗舰机混合档延迟、拔耳机不外放、判向准确率、待机电量。**关卡不过就砍功能，不砍质量。**
4. **分工**：Claude 写全部 Kotlin / Swift / Gradle / CI / 基准脚本并保证双端编译、单元测试通过；你负责真机运行与实测记录、Apple 开发者账号与签名、TestFlight / 内测 apk 分发、模型下载与许可复核、以及关卡拍板。
5. **节奏**：以里程碑 I0–I8 推进，每个里程碑结束时双端都能构建运行、验收项写入 `docs/验收记录/`。里程碑内部不再分周。

## 工作方式

- **分支与提交**：`main` 保持可构建；每个里程碑一个分支 `i0-baseline`、`i1-audio`…，验收通过后合并。提交信息前缀 `I0:`、`I1:`。
- **验收记录**：`docs/验收记录/I{n}.md` 记录验收项、真机型号、数据、未达标项与处置；关卡 A / B 单独成文。
- **不做的事**：不写商业化；不接任何自建后端；不内置 Key；测试用 Key 只放本机 SecureStore。
- **文档同步**：里程碑带来的设计变更回写到对应章节（02–08、附录 A），而不是只改代码。

## 风险与应对（执行层）

| 风险 | 应对 |
|---|---|
| AGP 9 + KMP 新插件坑多 | I0 严格照官方模板组合；不用 `android.library` 老插件 |
| sherpa-onnx iOS cinterop 链接失败 | I2 先用官方 `build-ios.sh` 产物 + `c-api.h`，失败则退到 Swift 桥（方案已列） |
| `core/nmt` 与 sherpa-onnx 共用 ORT 出现符号 / 版本冲突，或 opus-mt 在基线机延迟 / 发热超标 | I2 先验证单副本链接；不可解时 NMT 经 sherpa 暴露的 ORT 句柄或独立命名空间；基线机超标则离线档改逐句非流式、beam 1，关卡 A 记录数据后再定 |
| 关卡 A 基线机不达标 | 按路线图预案：基线机默认关声纹改固定方向、greedy 解码；不降低旗舰机指标 |
| 单人真机矩阵不够 | 优先 AirPods + 一副国产 TWS + 一台小米 / 华为；其余机型写入待验证，不承诺 |
| 范围回涨 | 任何新功能先问"直接服务实时线或会议卡吗"，否则进 v1.1 清单 |
