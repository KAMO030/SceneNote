# 01 · 产品定位与目标用户

> **这篇讲什么**：我们为什么做这个 App、做给谁、首页那五张场景卡分别解决什么问题、用户到底要点几下。
> **谁该看**：所有人。技术细节在 02 / 03 / 05–07。

## 先看这个

1. **识别准不准已经不是卖点**——iOS 26、Pixel、Google Translate 都很准。我们的卖点是：**用户每次录音前要做的五个决定（什么语言、要不要翻译、翻成什么、什么口气、输出什么格式）打包成一张"场景卡"，绑到一个物理入口，按一下就完事。**
2. **旗舰是实时翻译。** 苹果、谷歌、三星的系统翻译都有门槛（指定机型 + 指定耳机 + 账号，大陆用不了，没有中文方言，对方只能听外放或看屏幕，翻完就没了）。我们押注：任意手机 + 任意蓝牙耳机、方言、双方都私密、多人各听各的语言、不掏手机不外放、聊完自动变成纪要和词库。
3. **零 Key 也能用，但要诚实。** 不填任何云端 Key 时：能录、能转写（普通话 / 英文 / 粤语 / 四川话）、能规则整理、能出字幕、能分享；中 ↔ 英翻译零 Key 也能做（端侧 NMT，首次用前要下载约 80 MB / 方向的语言对模型，两端一致、不依赖系统）。**做不到**大模型级润色、上海话 / 闽南语识别、粤语真正翻成普通话、中英以外的语言对翻译——这些要么靠系统自带的大模型（新机型才有），要么靠用户自己的 Key（更多离线语言对 v1.1 评估）。
4. **明确不做**：自己的服务器 / 账号 / 社区；内置 Key；自有域名和 CDN；通话录音；外放当主入口；Material 3 界面。

---

## 1.1 为什么是"场景"

用户真正重复劳动的，不是按录音键，而是录之前的一堆选择。我们把这些选择做成场景卡：**入口、识别路线、方言、风格、翻译目标、输出模板、分享方式、隐私档，全是场景的参数**，不是设置页里的一堆下拉框。

举例：
- 按控制中心的"周会"按钮 → 自动用商务风、普通话、不翻译、纪要模板，录完 10 分钟内出一份能发群的纪要。
- 戴上耳机按一下 → 进入"面对面对话"，对方说英文你听中文，你说中文对方看屏幕上的英文。
- 在 YouTube 里拉下通知栏点"屏内翻译" → 字幕浮在视频上。

**我们给自己定的规矩**：每张 MVP 场景卡都要写出"从入口到出结果"的零点击路径，被迫点击数要数出来（见 1.4）。三态路由、隐私档、"谁在说"这类高级选项只出现在"复制一张卡再改"的编辑页里，场景卡表面最多两个语言标签。

## 1.2 为什么实时翻译是旗舰

三个理由：

1. **频次最高、体感最强**：问路、饭桌、小会、看视频每天都在发生；会议纪要一周一次。
2. **最难被系统预装同质化**：Apple Live Translation 要 iPhone 15 Pro + Apple Intelligence + 指定 AirPods，大陆用不了；Google 耳机翻译必须联网、没有中文方言；三星 Interpreter 只能对方外放。我们做的是"任意手机 + 任意 A2DP 耳机 + 方言 + 自带 Key + 双方私密 + 多人多语 + 聊完有沉淀"。
3. **让"越用越准"的飞轮从一周一转变成一天几转**：每次实时对话和每次看视频，结束后都自动进知识库、进词库，下次翻译更准（术语表在云端翻译和端侧 NMT 上都生效，零 Key 用户同样在环内，见 04）。

屏内翻译则押注：中文 / 方言 / 中英混说、Key 与端侧自由切换、机型无关、字幕和纪要进知识库；对 Netflix 这类 DRM 平台和 iOS 网页视频，我们直接标"不可用"，引导用系统自带的实时字幕。

| 中文职场记录者 | 录完 10 分钟内要一份能发群的纪要 | 会议卡（有 Key 或系统模型：纪要模板；零 Key：时间轴要点 + 待办候选写进提醒事项） | 日历会前通知、控制中心 / 磁贴 |
| 内容创作者 / 管理者 | 说比打字快，但口语不体面 | 口述成稿三子卡：发微信（口语）/ 写邮件（正式）/ 发社媒（短句 + 话题标签）。**风格由入口决定，不去猜你要发到哪个 App** | 快捷指令、Android 快捷方式、选中文本润色（辅助） |
| 学生 / 研究者 | 长录音、省电、术语准 | 课堂卡（v1.1）；看课程·笔记（v1.1，屏内） | 课表联动 |
| 记者 / HR / 医生律师 | 内容不能离开设备 | 采访卡（v1.1，默认"锁定"，任何东西不出手机） | Action Button |
| 客服 / 售后 | 通话后要工单与承诺句 | 客服卡（v2；不支持通话录音，只录面对面或外放） | 快捷指令 |

## 1.4 每张场景卡默认怎么工作

先解释两个会反复出现的设置：

- **隐私档（四档）**：**锁定**（什么都不出手机，连局域网也不发）/ **仅本机 + 逐段授权**（默认不出站，用户可以按段点"精修这一段"）/ **仅文本上云**（录音不出手机，只有文字去云端润色翻译）/ **音频上云**（录音也可以发给云端识别）。
- **路由（三态）**：**仅本机 / 自动 / 优先云端**，决定识别在哪做。两者怎么组合、哪些组合不合法，见 02 的 2.5。

| 场景 | 路由 | 识别实际怎么跑 | 风格 | 翻译 | 隐私档 | 输出 | 阶段 |
|---|---|---|---|---|---|---|---|
| **面对面对话（旗舰）** | 自动 | 端侧流式识别（中 ↔ 英自动判向）；粤语 / 四川话走非流式模型，只做单向的 M0 仅听；对方说日 / 韩 / 欧语要在线档 + Key；翻译有 Key 用云端（qwen-mt / Haiku），没 Key 用端侧 NMT（中 ↔ 英，语言对模型没下载时提示下载）；译文用系统语音进耳机（无语音包时 sherpa-onnx Matcha 兜底）；**对方的声音默认不存，只存文字** | 口语（一句话级的语气提示） | 双向 | 仅文本上云 | 对话卡片（双语对照 + 要点）+ 会后纪要 + 新词候选 | **MVP**：M0 / M1 / M3 / M4；v1.1：M5 / M8 / M9 / M12；v2：M10 / M11 / M6 / M7 |
| 速译一句（M4 子卡） | 自动 | 端侧识别 + 快速翻译 → 屏幕大字朝向对方 | 跟场景（旅行口语 / 商务正式） | 单向 我 → 对方 | 仅文本上云 | 大字卡 | MVP |
| 讲座旁听 | 自动 | 端侧流式 + 翻译进耳机；锁定方向，只过滤掉"我自己的声音" | 学术 | 单向 对方 → 我 | 仅文本上云 | 时间轴要点 + 术语候选 | v1.1 |
| **屏内 · 看视频字幕** | 自动 | S4：解码文件 → 端侧批量识别（比实时快好几倍）→ 翻译 → 字幕，播放追上转写就自动暂停等一下；S1（Android）：抓系统声音 → 流式识别 → 画中画字幕，落后画面 1.5–3 秒；S8：用麦克风听外部设备 | 字幕语体（口语、每条不超两行） | 源语 → 系统语言 | 仅文本上云 | SRT / VTT 字幕 + 生词抽屉 + 分享卡片 | **MVP**：两端 S4 / S8，Android S1 + S3；v1.1：S2 / S5 / 悬浮窗；v2：S6 / S7 |
| 屏内 · 看课程笔记 | 自动 | 同上 | 学术 | 同上 | 仅文本上云 | 章节 / 术语 / 纪要 | v1.1 |
| 屏内 · 看剧口语 | 自动 | 同上 | 口语 | 同上 | 仅文本上云 | 双语对照 + 口语句摘录 | v1.1 |
| 会议 | 自动 | 端侧流式草稿 + 端侧定稿；录音不上云；有 Key 时文字交云端 LLM 写纪要 | 商务 | 关（有外方用面对面卡） | 仅文本上云 | 有 LLM：议题 / 结论 / 待办 / 承诺句；无 LLM：时间轴要点 + 待办候选 | MVP |
| 口述成稿（3 子卡） | 仅本机 | 端侧识别；文字交云端 LLM 或系统模型润色 | 子卡决定 | 关 | 仅文本上云 | 文体段落 | MVP |
| 方言家庭 | 自动 | 粤语 / 四川话端侧；上海话 / 闽南语 MVP 在这张卡里直接隐藏 | 口语 | 方言原文 → 普通话（简 / 繁）→ 可选外语；零 Key 只做繁简转换并标注 | 仅本机 + 逐段授权 | 留言卡 | MVP |
| 课堂 | 仅本机 | 端侧小模型、省电 | 学术 | 外语课开 | 仅本机 + 逐段授权 | 章节 / 术语 / 问题 | v1.1 |
| 采访 | 仅本机 | 端侧 + 说话人标记 | 中性 | 关 | **锁定** | 问答分段 | v1.1 |
| 客服 | 自动 | 端侧识别；文字交 LLM 抽承诺句 | 正式 | 关 | 仅文本上云 | 问答 + 承诺句 + 工单 | v2 |

首次打开只看到五张卡：**面对面对话（置顶）、屏内字幕、会议、口述成稿（一张卡展开三子卡）、方言家庭**。其他场景折叠在"更多"里；自定义场景只能"复制一张再改"，避免配置越来越复杂。

**默认的云端策略一句话**：端侧识别 + 只有文字上云（润色 / 翻译）。录音要上云，只有在用户明确选了"优先云端"或"在线档"、明确改了隐私档、或按段点了授权时才会发生。

## 1.5 零点击路径：到底要点几下

| 场景 | 路径 | 被迫点击数 | 说明 |
|---|---|---|---|
| 面对面 · M0 仅听 | 出门时预热一次（手机放胸前口袋 / 手持 / 挂绳）→ 对方开口 → 耳机单击或 Action Button → 震动两短确认（1–2 秒重新加载）→ 译文进耳机 | 1 | 目标是对方说完 1.5 秒内听到译文（要真机验收后才写进文案）；裤兜姿态收音效果待实测；冷启动或被打断后需要"解锁点一下"，我们不假装能后台恢复 |
| 面对面 · M1 耳听·面屏 | 在 M0 基础上掏出手机 → 解锁 → 竖起来朝向对方（前台亮屏时自动进入）→ 对方看到礼貌卡和字幕 | 1–2 | 摘下耳机自动降到 M3 双屏；"我不用了谢谢"一键退回 M0 |
| 面对面 · M4 速译一句 | Action Button / 磁贴长按说话 → 松手 → 大字朝向对方 | 1–2 | 说完约 1 秒出字 |
| 屏内 · S4 文件字幕 | 相册 / 微信视频 → 分享 → 场记 → 自动开始 → 首条字幕约 3–5 秒 | 2 | 语言自动检测，目标语 = 系统语言；处理过的视频打开即播 |
| 屏内 · iOS 看其他 App 里的视频（MVP 降级） | 在视频 App 里保存到相册 / 存到文件 / Safari 下载 → 分享给场记 → S4 | 3–4 | iOS MVP 对其他 App 正在播的视频没有 App 内路径 |
| 屏内 · S1 系统字幕（Android） | 在 YouTube 里下拉点磁贴 → 系统投屏弹窗点"开始" → 画中画字幕条出现 | 冷启动 3 步 ≤ 8 秒；热启动 2 步 ≤ 5 秒 | 系统弹窗每次都躲不掉，披露页提前说明；2 秒探测发现抓不到声音就自动换 S3 / S8 |
| 会议 | 会前通知"一键开录《周会》" → 录 → 停 → 10 分钟内成稿 → 通知"分享？" → 分享面板 | 3 | 零 Key 时成稿是时间轴要点，一样能分享 |
| 口述成稿 · 发微信 | 快捷指令 / 磁贴（参数 = 发微信）→ 说 → 停 → 自动复制到剪贴板 + 卡片预览 → 去微信粘贴 | 2 | 系统不告诉我们你要发到哪个 App，所以靠入口参数决定风格 |
| 方言家庭（晚辈侧） | 微信语音"用其他应用打开" → 场记 → 自动出留言卡 → 分享回微信 | 2 | 长辈零安装；晚辈也可以直接对着长辈录，或戴耳机 M0 仅听 |

## 1.6 版本与团队假设

- Kotlin 2.4.0 / Compose Multiplatform 1.12.0 / sherpa-onnx 1.13.8 / Ktor 3.5.2 / SQLDelight 2.3.2 / Koin 4.2.2；Android minSdk 26；**iOS 17 起**（能力按 17 / 18 / 26 / 27 分层，iOS 16 不支持）。
- 团队 6 人（2 KMP/Compose、1 音频与实时管线、1 iOS 原生、1 Android 原生、1 全栈兼 CI）；MVP 18 周，第 4 周和第 10 周各有一道 go/no-go 关卡（见 10）。如果只有 4 人，MVP 拉长到 24 周或砍范围。
- 产品名保留"场记 SceneNote"。备选名"耳译"更贴旗舰，但会把会议、口述、屏内字幕挤出语义。
